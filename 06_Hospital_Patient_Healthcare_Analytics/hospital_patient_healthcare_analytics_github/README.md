# Hospital Patient & Healthcare Analytics

An advanced SQL portfolio project built with **PostgreSQL**. It explores fictional hospital operations through patient demographics, admissions, diagnoses, doctor workload, bed utilization, readmissions, billing, and payment collections.

> **Privacy and safety:** This repository uses synthetic, fictional records generated by SQL. It contains no real patient records and must not be populated with identifiable patient or protected health information.

## Project goals

- Track patient and admission trends over time.
- Analyze admission types, length of stay, and discharge patterns.
- Compare doctor workload and department-level activity.
- Understand diagnosis distribution.
- Monitor bed capacity and current occupancy.
- Identify 30-day readmission candidates using a simple operational definition.
- Measure billed revenue, payments received, and outstanding balances.

## Technology

- PostgreSQL 14+
- SQL: joins, CTEs, subqueries, window functions, aggregations, views, indexes, date functions
- Optional visualization: Power BI or Tableau

## Quick start

1. Install PostgreSQL 14 or later and open pgAdmin or `psql`.
2. Create a project database:

   ```sql
   CREATE DATABASE hospital_analytics;
   ```

3. Connect to `hospital_analytics`.
4. Run the SQL scripts in this order:

   | Order | File | Purpose |
   |---:|---|---|
   | 1 | `sql/01_schema.sql` | Create relational tables and constraints |
   | 2 | `sql/02_generate_synthetic_data.sql` | Generate fictional sample data |
   | 3 | `sql/04_views.sql` | Create reusable analytical views |
   | 4 | `sql/03_analysis_queries.sql` | Run the business analysis queries |
   | 5 | `sql/05_indexes_and_performance.sql` | Add indexes and inspect query plans |

   Example with `psql`:

   ```bash
   psql -U postgres -d hospital_analytics -f sql/01_schema.sql
   psql -U postgres -d hospital_analytics -f sql/02_generate_synthetic_data.sql
   psql -U postgres -d hospital_analytics -f sql/04_views.sql
   ```

   Run each query in `03_analysis_queries.sql` separately in pgAdmin Query Tool or `psql`.

## KPI definitions and caveats

| KPI | Project definition |
|---|---|
| Unique patients | Distinct patients with at least one admission |
| Admissions | Count of admission records |
| Average length of stay | Average calendar-day difference between discharge and admission for discharged records |
| 30-day readmission candidate | A subsequent admission 1–30 days after a recorded discharge |
| Bed occupancy snapshot | Beds linked to currently admitted records divided by active beds |
| Collection rate | Completed payments divided by total billed amount |
| Outstanding balance | Billed amount less completed payments |

These are portfolio-level operational definitions, not validated clinical or regulatory measures. A production readmission measure needs a defined eligible population, exclusions, risk adjustment, and clinical validation. A true bed occupancy rate should use time-based bed census or bed-days; the supplied query is a simplified snapshot.

## Performance exploration

The performance script creates indexes on common filter and join columns, runs `ANALYZE`, and includes an `EXPLAIN (ANALYZE, BUFFERS)` example. On a small synthetic dataset PostgreSQL may correctly choose a sequential scan; index benefits are easier to observe at larger scale.
