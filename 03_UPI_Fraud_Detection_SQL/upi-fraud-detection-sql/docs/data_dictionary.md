# Data dictionary

All data is synthetic, generated by `data_generator/generate_data.py` (seed 42). It covers 1 July – 30 September 2026.

## `upi` schema – source data

### `upi.cities` (25 rows)
| column | type | notes |
|---|---|---|
| city | text PK | e.g. Mumbai, Patna, Kochi |
| state | text | |
| latitude, longitude | numeric(8,5) | used by R02 haversine distance |

### `upi.accounts` (~50k rows)
| column | type | notes |
|---|---|---|
| account_id | int PK | |
| vpa | text unique | UPI ID, e.g. `rahul.sharma42@oksbi` |
| holder_name | text | random Indian name or shop name |
| bank_name | text | |
| account_type | text | `PERSONAL` or `MERCHANT` |
| merchant_category | text | merchants only (GROCERY, FUEL, … GIFT_CARDS_CRYPTO) |
| home_city | text FK → cities | |
| created_at | timestamp | about 3 % of accounts open during the window |
| kyc_level | text | `MIN` or `FULL` |

### `upi.transactions` (~5.9 lakh rows)
| column | type | notes |
|---|---|---|
| txn_id | bigint PK | |
| txn_ts | timestamp | |
| payer_account_id / payee_account_id | int FK → accounts | always different |
| amount | numeric(12,2) | ₹1 – ₹1,00,000 |
| txn_type | text | `P2P` (person to person) or `P2M` (person to merchant) |
| channel | text | `QR`, `INTENT`, `COLLECT`, `VPA_ENTRY` |
| device_id | text | the payer's device; a new id means a new phone |
| txn_city | text FK → cities | where the payment was made from |
| status | text | `SUCCESS` or `FAILED` |
| failure_reason | text | `INSUFFICIENT_FUNDS`, `BANK_TIMEOUT`, `WRONG_PIN` (failed only) |

**Indexes:** `(payer_account_id, txn_ts)`, `(payee_account_id, txn_ts)`, a partial index on wrong-PIN failures, and a BRIN index on `txn_ts`.

## `eval` schema – ground truth and grading (never read by the rules)
| table | contents |
|---|---|
| `fraud_labels` | `txn_id`, `fraud_pattern` for every planted fraud payment |
| `scored_transactions` | every transaction with its label, score and alert flag |
| `overall_metrics` | confusion matrix, precision, recall, F1, money caught |
| `rule_performance` | per rule: alerts, TP / FP, precision, recall on its target pattern |
| `pattern_coverage` | per planted pattern: planted, caught, recall, value |
| `threshold_curve` | precision and recall for thresholds 25…100 |

## `fraud` schema – the engine
| table | contents |
|---|---|
| `rule_config` | rule catalogue: name, target pattern, severity, JSONB thresholds, on/off switch |
| `risk_bands` | score ranges → band → action |
| `rule_hits` | one row per (txn, rule) with JSONB evidence |
| `txn_risk_scores` | one row per alerted txn: score, band, action, rules fired, merged evidence |
| `account_risk_profile` | one row per suspicious account: alert counts, rules, risk score, investigation tier |
| `mule_chains` | one row per hop of each detected mule chain |
| `suspected_mule_accounts` | accounts that received and forwarded chain money |
| `engine_run_log` | per step: rows written, runtime |

## `analytics` schema – reporting views
`kpi_summary`, `daily_alert_trend`, `hourly_risk_heatmap`, `city_risk`, `channel_risk`, `rule_overlap`, `top_risky_accounts`, `mule_network_edges`, `alert_queue`.

## Planted patterns (generator)
| pattern | what the generator does |
|---|---|
| VELOCITY_BURST | 8–15 payments 20–75 s apart from a new device to 1–3 mules, plus slow 4–5-payment variants |
| IMPOSSIBLE_TRAVEL | a genuine home-city payment, then one ≥ 800 km away 8–45 min later from a new device |
| MULE_CHAIN | victim → 3–5 mules (each forwarding 96–99.5 % within 4–40 min) → cash-out merchant, plus slow variants |
| NEW_DEVICE_HIGH_VALUE | first payment from a new device, ₹25k+ and 15–40× normal spend |
| STRUCTURING | 5–9 payments of ₹9,500–9,999 in one day, plus a 3 + 3 two-day variant |
| FAN_IN_COLLECT_SCAM | new account receives 12–30 collect payments from distinct people within ~20 h |
| ODD_HOUR_ANOMALY | 1–4 am payment 12–30× normal spend |
| PIN_BRUTE_FORCE | 3–6 wrong-PIN failures in about 4 min, then a successful ₹10k–60k payment |

**Unlabelled genuine traps** (they cause the false positives): a new phone used to pay rent, mall shopping sprees, group trip collections, late-night emergency payments, and rent split into ₹9,800 parts.
